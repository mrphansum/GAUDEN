################################################################################
# PHẦN B — KIẾN TRÚC TRONG ĐẦU (VIẾT TRƯỚC KHI GÕ CODE)
################################################################################

B1. Vấn đề app giải quyết
  - Bán MODULE (Add-on / DLC) dạng Non-Consumable IAP.
  - Guest xem DEMO; mua phải login; server giữ entitlement (Purchase).
  - Token access ngắn + refresh dài (Keychain); không biometric.

B2. Hai “source of truth”
  - Ai là user?     → JWT sub + collection users
  - Đã mua gói?     → collection purchases (SAU /iap/verify)
  - Giá tiền?       → App Store (StoreKit), không hardcode trên server

B3. Layer backend
  Request HTTP
    → middleware (helmet, cors, json, rate-limit, auth)
    → routes (validate body, gọi service, res.json)
    → services (logic: token, google, iap)
    → models (Mongoose schema → MongoDB)

B4. Layer iOS
  View (SwiftUI)
    → AppState (session UI)
    → *Service (Auth / Module / IAP)
    → APIClient (HTTP + refresh 401)
    → TokenStore → KeychainStore
    → StoreKit (chỉ khi mua)

  final class APIClient: @unchecked Sendable
    static let shared
    private session: URLSession
    private refreshLock, isRefreshing

    var tokenProvider: (() -> TokenPair?)?
      (chức năng) Callback đọc token — gán từ AppState.init
    var refreshHandler: (() async throws -> Void)?
      (chức năng) Callback refresh — gán gọi AuthService.refreshTokens

    func request<T: Decodable>(path, method, body, authorized, retryOnUnauthorized) async throws -> T
      (chức năng) requestData + JSONDecoder → T
      [TRỎ TỚI] requestData, AppConfig.apiBaseURL (gián tiếp)

    func requestData(...) async throws -> Data
      (chức năng) Build URLRequest → URLSession.data → handle status
      Bước trong hàm (viết đúng thứ tự):
        1. URL relative AppConfig.apiBaseURL
        2. method, headers Accept/Content-Type
        3. nếu authorized: Bearer từ tokenProvider
        4. encode body nếu có (AnyEncodable)
        5. session.data
        6. nếu 401 + authorized + retry → refreshIfNeeded → gọi lại 1 lần
        7. không 2xx → APIError
        8. return Data

    private func refreshIfNeeded() async throws
      (chức năng) Chỉ 1 refresh tại 1 thời điểm; gọi refreshHandler

  private struct AnyEncodable: Encodable
    (chức năng) Type-erase body Encodable để encode generic

  [ĐƯỢC GỌI BỞI] AuthService, ModuleService, IAPService

  Ghi chú học:
    - Mọi network iOS CHỈ đi qua class này → dễ debug 1 chỗ.
    - retryOnUnauthorized: false khi đang gọi /auth/refresh (tránh vòng lặp).

  Windows:
    [ ] Mongo chạy

    [ ] npm run dev → /health ok

E3. Lỗi thường gặp khi tự viết lại

  1) CORS / connection refused
     → backend listen 0.0.0.0; firewall Windows; đúng IP
  2) ATS blocked HTTP
     → Info.plist NSAllowsLocalNetworking / ArbitraryLoads (dev)
  3) Decode fail
     → field JSON backend ≠ CodingKeys iOS
  4) 401 loop
     → /refresh phải retryOnUnauthorized: false
  5) Mua 403 / full null
     → quên Bearer hoặc verify chưa tạo Purchase
  6) Google prod fail
     → thiếu GOOGLE_CLIENT_ID; dev JWT chỉ work khi NODE_ENV development

# PHẦN I — NGUYÊN TẮC KHI VIẾT LẠI (KỸ SƯ GIỎI LÀM GÌ)
################################################################################

  1. Boundary rõ: View không gọi URLSession; View không đụng Mongo.
  2. Secret không hardcode production; .env / Keychain đúng chỗ.
  3. Server là trọng tài ownership — client chỉ là UX.
  4. Idempotent IAP: verify 2 lần không tạo 2 purchase lỗi.
  5. Refresh rotate: token cũ chết ngay khi dùng.
  6. Lỗi có message; HTTP status có nghĩa; UI empty/loading/error đủ 3 trạng thái.
  7. Module-first: thêm gói = data + App Store product, không fork app.
  8. Viết comment “tại sao” (why), không comment “code làm gì” hiển nhiên.
  9. Mỗi PR/ngày chỉ 1 vertical slice (vd: login end-to-end) thay vì 20 file nửa vời.
 10. Đọc CALL_CHAIN khi debug; đọc DATA_FLOW khi sai JSON; đọc LUONG khi sai nghiệp vụ.
